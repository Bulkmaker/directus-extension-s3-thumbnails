# Changelog — directus-extension-s3-thumbnails

> **Легенда «Безопасно обновлять»:** ✅ да (обратно совместимо) · ⚠️ с проверкой (протестировать на dev) · ❌ breaking (читать перед обновлением).

## [0.5.0] — 2026-10-03
### Added
- **Видео-постеры** (опция `THUMBNAILS_VIDEO_POSTERS=true`, **по умолчанию выключена**): при загрузке `video/*` ffmpeg снимает кадр (сек. 1, при отсутствии — первый) и кладёт его вариантами тех же пресетов по тому же пути, что миниатюры картинок: `<preset.key>/<basename>.<format>`. Фронт использует тот же `imageUrl(file, preset)`.
- ENV: `THUMBNAILS_VIDEO_MAX_MB` (500), `THUMBNAILS_VIDEO_TIMEOUT_SEC` (60), `THUMBNAILS_FFMPEG_PATH`, `THUMBNAILS_FFMPEG_DOWNLOAD` (true), `THUMBNAILS_FFMPEG_DIR`.
- ffmpeg: если его нет, расширение скачивает статический бинарь (ffmpeg-static b6.1.1, проверка sha256; linux x64/arm64, alpine/musl). Видео читается по Range через локальный прокси к S3 (без полной загрузки), запасной путь — временный файл.
- Регенерация (`POST /thumbnails/regenerate`, кнопка в модуле) обрабатывает и видео при включённой опции; `GET /thumbnails/stats` отдаёт `totalVideos`.
- Тесты (vitest): `npm test`.

### Fixed
- Удаление файла не чистило варианты в S3: для `directus_files` Directus шлёт события `files.delete` (а не `items.delete`), хук их не получал. Добавлены `filter('files.delete')` + `action('files.delete')` — варианты картинок и видео удаляются вместе с файлом (трогаются только объекты `<preset>/<basename>.*` удаляемого файла).

**Безопасно обновлять:** ✅ да — опция выключена по умолчанию, без `THUMBNAILS_VIDEO_POSTERS=true` поведение для картинок прежнее (кроме исправленной чистки вариантов при удалении файла). Новых npm-зависимостей в рантайме нет (sharp берётся из образа Directus, ffmpeg скачивается самим расширением), в Dokploy-обёртке ничего менять не нужно.

## [0.4.3] — 2026-07-09
### Fixed
- Сборка dist переведена на `--no-minify`: минифицированная сборка отдавала устаревший dist (кэш build-тула) — CI публиковал старый код.
- AssetsService создаётся с admin-accountability (вместо null) — устойчивее к permission-краям при внутренней генерации.
- В лог ошибки генерации добавлено имя класса ошибки (DirectusError vs S3) — быстрее диагностировать «Forbidden = отсутствует оригинал в хранилище».

**Безопасно обновлять:** ✅ да (обратно совместимо; dist крупнее из-за отказа от минификации).

## [0.4.2] — 2026-07-09
### Fixed
- Запись превью в S3 больше не падает на бэкендах, запрещающих per-object ACL
  (Beget S3 при публичной bucket-политике отбивал `PutObject` с `ACL: public-read`
  как «AccessDenied»). Теперь при отказе по ACL превью пишется без ACL (объект и так
  публичен через bucket-политику), результат кэшируется на процесс.

**Безопасно обновлять:** ✅ да (обратно совместимо: где ACL работает — ставится как прежде).

## [0.4.1] — 2026-07-09
### Changed
- CI-сборка dist; детект устаревших пресетов при смене конфига
- Сборка `dist` — в GitHub Actions (при пуше в `src`), `dist` коммитится в `main`.

**Безопасно обновлять:** ✅ да.
